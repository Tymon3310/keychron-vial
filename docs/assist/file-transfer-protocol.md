# File Transfer Protocol

Keychron Assistant features an integrated peer-to-peer file transfer engine
embedded within the cross-screen subsystem. It allows users to drag-and-drop
files across the screen boundary or use an in-app file browser to stream files
directly between paired computers.

---

## 1. Overview & Constraints

- **Transport:** UDP / Reliable Datagram sliding window
- **Concurrent Queue Limit:** Up to 10 files queued at a time (transferred sequentially)
- **Default Destination Folder:**
  - Windows: `%USERPROFILE%\Downloads\Keychron_Screen\`
  - macOS: `~/Downloads/Keychron_Screen/`
  - Configured at runtime via Tauri IPC command `set_rdp_file_folder`
- **Supported File Types:** All binary and text formats
- **File Handling:**
  - Duplicate naming resolution (automatic `(1)`, `(2)` incrementing, with error guard `no available duplicate file name`)
  - Chunked retransmissions with batch acknowledgment (`FileBatchAck`)
  - Real-time progress, throughput, and elapsed time calculation

## 2. Protocol State Machine & Phases

```
Sender (Initiator)                                 Receiver (Target)
        │                                                  │
        │  1. FileStart (id, name, size, chunk_size)       │
        ├─────────────────────────────────────────────────►│  (Creates target file
        │                                                  │   in ~/Downloads/Keychron_Screen)
        │                                                  │
        │  2. FileData [Chunk 0, Offset 0]                 │
        ├─────────────────────────────────────────────────►│
        │  2. FileData [Chunk 1, Offset 64KB]              │
        ├─────────────────────────────────────────────────►│
        │  ... (Sliding window batch)                      │
        │                                                  │
        │  3. FileBatchEnd (id, batch_idx)                 │
        ├─────────────────────────────────────────────────►│
        │                                                  │
        │  4. FileBatchAck (id, batch_idx, status)         │
        │◄─────────────────────────────────────────────────┤  (Verifies received bytes)
        │                                                  │
        │  [Repeats for all batches...]                    │
        │                                                  │
        │  5. FileEnd (id, checksum)                       │
        ├─────────────────────────────────────────────────►│  (Flushes to disk,
        │                                                  │   verifies integrity)
        │  6. FileResult (id, status: Success)             │
        │◄─────────────────────────────────────────────────┤
```

## 3. Packet Format & Notification Types

File transfer packets are wrapped in the `GlobalUdpEvent` container and carry
`RdpNotify` payloads matching specific phase enums:

### 1. `FileStart`
Announces an outgoing file transfer:
```rust
RdpNotify<(String, String, u64, u64, String)>
```
- `tuple.0` (`String`): Transfer UUID (`file_id`, generated by `crypto.randomUUID()`)
- `tuple.1` (`String`): File name (e.g., `"firmware_update.bin"`)
- `tuple.2` (`u64`): Total file size in bytes
- `tuple.3` (`u64`): Chunk size in bytes (typically 65,536 bytes / 64 KB)
- `tuple.4` (`String`): Checksum or source metadata

### 2. `FileData`
Streams binary payload chunks:
```rust
RdpNotify<(String, u64, u64, Vec<u64>)>
```
- `tuple.0` (`String`): Transfer UUID (`file_id`)
- `tuple.1` (`u64`): Byte offset within the file
- `tuple.2` (`u64`): Byte length of this chunk
- `tuple.3` (`Vec<u64>`): Packed payload words. The native binary's monomorphized
  serde type confirms this tuple shape; confirm word-to-byte order against a
  native transfer before treating the current little-endian Linux encoding as
  interoperability-verified.

### 3. `FileBatchEnd`
Indicates the end of a transmission batch (window):
```rust
RdpNotify<(String, u64, u64)>
```
- `tuple.0` (`String`): Transfer UUID (`file_id`)
- `tuple.1` (`u64`): Batch sequence index
- `tuple.2` (`u64`): Batch byte count (field position/type confirmed from the
  native binary; semantic interpretation still needs a peer interoperability
  test).

### 4. `FileBatchAck`
Sent by the receiver to confirm receipt of all chunks in a batch:
```rust
RdpNotify<(String, u64, String)>
```
- `tuple.0` (`String`): Transfer UUID (`file_id`)
- `tuple.1` (`u64`): Batch sequence index acknowledged
- `tuple.2` (`String`): Status (`"ok"` or error code)

If an ack is not received within the retry timeout, the sender replays the
missing chunks from `PendingFileBatch` (managed in a `BTreeMap<u64, PendingFileBatch>`).

### 5. `FileEnd`
Signals that the final byte has been sent:
```rust
RdpNotify<String> // Carrying file_id
```

### 6. `FileMissing`
Sent if the source file was moved, deleted, or unreadable during transfer:
```rust
RdpNotify<String> // Carrying file_id
```

### 7. `FileCancel`
Transmitted when either party cancels an active transfer:
```rust
RdpNotify<String> // Carrying file_id
```
- On receipt, the partial download is deleted and the transfer status is marked as `"cancelled"`.

### 8. `FileTransferSwitch`
Transmitted to toggle file transfer capabilities dynamically between peers:
```rust
RdpNotify<bool> // true = enabled, false = disabled
```

## 4. History & Persistence (`FileTransferHistoryRecord`)

Every transfer attempt (successful, failed, or cancelled) is recorded in
`~/.Keychron_Screen/file_transfer_history.json`.

### Record Schema (15 Fields)

```rust
pub struct FileTransferHistoryRecord {
    pub id: String,
    pub device_id: String,
    pub device_name: String,
    pub name: String,
    pub path: String,
    pub directory_path: String,
    pub direction: String,        // "send" | "receive"
    pub status: String,           // "sent" | "received" | "failed" | "cancelled" | "receive_error"
    pub size_bytes: u64,
    pub transferred_bytes: u64,
    pub average_speed_bytes_per_second: u64,
    pub started_at: u64,          // Unix timestamp in milliseconds
    pub completed_at: Option<u64>,
    pub elapsed_ms: u64,
    pub error: Option<String>,
}
```

## 5. UI Notification Codes

The frontend listens for `FileTransfer` events and binds error messages to i18n tokens:

| Status / Error | i18n Token | Description |
|----------------|------------|-------------|
| `peer_cancelled` | `cross.file_transfer.peer_cancelled` | The remote computer cancelled the transfer |
| `file_missing` | `cross.file_transfer.file_missing_desc` | Original file not found on disk |
| `file_limit` | `cross.file_transfer.file_limit_desc` | Exceeded 10 file queue limit |
| `receive_failed` | `cross.file_transfer.receive_failed_desc` | Disk write error or incomplete payload |
| `send_failed` | `cross.file_transfer.send_failed_desc` | Network dropped during transmission |
| `unsupported` | `cross.file_transfer.unsupported_file` | Unsupported file attributes or socket error |
